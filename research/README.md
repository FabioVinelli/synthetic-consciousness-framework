# Research provenance

This directory establishes how SCF preserves the lineage of ideas. Original historical/source material must remain distinguishable from later interpretation, computational abstraction, hypotheses, implementation, and experimental results.

## Provenance layers

| Layer | What it contains | Attribution and evidence rule |
| --- | --- | --- |
| Original historical/source material | Original works, editions, excerpts, and historical records | Preserve author, edition, exact locator, and publication status; distinguish direct access from secondary reporting |
| Later interpretation | Summaries, translations, comparisons, and commentary | Identify the interpreter and source; do not assign added claims to the original author |
| Computational abstraction | Operational mechanisms inspired by selected concepts | Credit the adaptation and explicitly limit the analogy |
| Hypothesis | Testable predictions about those mechanisms | Specify intervention, controls, metrics, and disconfirming outcomes |
| Implementation | Code and configurations intended to operationalize a mechanism | Link to the specification; implementation alone is not evidence of effectiveness |
| Experimental result | Recorded outcomes and analyses | Link inputs, methods, versions, failures, and scope of inference |

These are logical provenance layers. This first commit does not create an implementation, experiment dataset, or complete source archive.

## Required provenance for future additions

Record source identity, author, edition/version, exact locator, direct versus secondary access, quotation versus paraphrase, translation or interpretation responsibility, verification status, and permitted publication scope. Link each computational interpretation to the relevant source concept and each result to its actual experiment.

Keep corrections and unresolved attribution questions visible rather than silently rewriting the intellectual lineage.
